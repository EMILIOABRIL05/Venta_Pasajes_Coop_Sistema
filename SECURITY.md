# Política de seguridad

## Versiones con soporte

El proyecto se encuentra en desarrollo activo. Las correcciones de seguridad se
priorizan sobre la rama `develop` y sobre la versión estable más reciente cuando
exista una publicación de producción.

| Versión | Soporte |
| ------- | ------- |
| `develop` | Sí |
| Última versión estable etiquetada | Sí |
| Versiones anteriores | No garantizado |

## Reporte de vulnerabilidades

No publiques vulnerabilidades en issues públicos. Repórtalas por uno de estos
canales:

- Enviando un correo a `[tu-email@dominio.com]`.
- Contactando al responsable del repositorio en GitHub: `[usuario-de-github]`.
- Usando un reporte privado de seguridad de GitHub si está habilitado.

Incluye, si es posible:

- Descripción clara del problema.
- Pasos para reproducirlo.
- Impacto potencial sobre datos, pagos, boletos, usuarios o permisos.
- Versión, rama o commit afectado.
- Evidencia técnica mínima, como capturas, logs o prueba de concepto segura.

## Tiempos de respuesta

- Acuse de recibo: hasta 3 días hábiles.
- Evaluación inicial: hasta 7 días hábiles.
- Plan de mitigación o corrección: hasta 14 días hábiles, según severidad.

Las vulnerabilidades críticas que afecten ventas, cobros, autenticación,
permisos, datos personales o validación de boletos QR tendrán prioridad máxima.

## Divulgación responsable

Solicitamos no divulgar públicamente la vulnerabilidad hasta que exista una
corrección disponible o una mitigación aceptada por el equipo mantenedor.

## Alcance

Esta política cubre el código de aplicación, configuración, dependencias,
control de acceso, manejo de pagos, generación de boletos, validación QR y
protección de datos personales usados por el sistema.
